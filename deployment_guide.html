Master Deployment Guide

Step-by-step instructions for deploying the Hardened Architecture to production.

1

KV Namespace Setup

To enable the caching layer and prevent D1 quota exhaustion, create the following KV namespace in the Cloudflare Dashboard:

# Create via Wrangler CLI wrangler kv:namespace create PRODUCT_CACHE

Update your frontend/wrangler.jsonc to bind the namespace:

"kv_namespaces": [ { "binding": "PRODUCT_CACHE", "id": "YOUR_GENERATED_KV_ID" } ]
2

Configure Environment Variables

Deploy the following secrets and variables to both the Frontend and Sync Worker environments.

Variable Purpose Required
MP_API_KEY Marketplace API Authentication Yes (Secret)
D1_DATABASE_ID Primary Database Binding Yes
SYNC_BATCH_SIZE KV/D1 Batching Threshold (Recommended: 50) Yes
CIRCUIT_BREAKER_THRESHOLD Max API failures before trip (Recommended: 5) Yes
3

Deployment Sequence

Run the following commands in order to ensure database migrations are applied before the application boots.

# 1. Apply Database Migrations wrangler d1 migrations apply lanus-db --remote # 2. Deploy Sync Worker cd workers/sync-worker && wrangler deploy # 3. Deploy Frontend Application cd frontend && npm run build && wrangler deploy

✓ Post-Deployment Verification

Perform these tests to certify the stability of the environment.

Critical Path: Navigate Home → Product → Checkout. Ensure zero 500 errors.
Edge Case: Access a non-existent product URL. Confirm graceful 404 instead of server crash.
Admin Stability: Open /admin/products. Confirm pagination loads quickly.
B2B Rules: Verify Admin /admin/rules loads without timeout.
Sync Health: Trigger a manual Sync Worker run. Check logs for "Batching" events.
